# Claim Checklist

Use this checklist before turning a generated brief into public video copy.

- Keep claims that are backed by README, docs, package metadata, fixtures, or tests.
- Rewrite claims that depend on intention rather than shipped behavior.
- Avoid mentioning test coverage unless the target repository exposes a test command or test files.
- Run demo commands before recording them.
- Mark weak claims as roadmap items instead of current capabilities.
